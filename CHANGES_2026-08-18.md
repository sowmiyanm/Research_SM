# Changes — 18 Aug 2026

Six changes: five bug fixes from Review #5, plus entry/exit levels. Every one verified by re-running the pipeline over cached data.

---

## 1. Excel cache no longer strips `high`/`low`

**`data_cache.py`** — the backup column list omitted `high`/`low`, so the Excel file wasn't a faithful backup. When a pickle was missing, `load_ticker_data` fell back to Excel and both `calculate_52week_metrics` and `calculate_squeeze` silently took their close-only branches with nothing logged.

Now includes them, and filters to columns that actually exist so older frames still save.

**Verified**

```
Excel backup columns: ['date','close','high','low','traded_quantity','delivery_quantity','delivery_pct']
after deleting the pickle, load returns: ['date','close','high','low','traded_quantity','delivery_quantity']
legacy frame with no high/low still saves cleanly
```

## 2. Corporate-action threshold 15% → 30% (configurable)

**`calculations.py`**, new key `corp_action_gap_threshold_pct`.

NSE applies 20% price bands to most non-F&O stocks, so a small-cap hitting the circuit prints a clean ±20.0% move that is *not* a corporate action. At 15% the detector flagged 83 of 296 tickers — and because the shortlist excludes on `.any()`, a quarter of the universe was quarantined.

**Verified**

```
flags: 83/296 (28%)  →  8/296 (3%)
```

The 8 remaining are the genuine ones: V2RETAIL −89.8, KOTAKBANK −80.3, MCX −79.8, JLHL −79.5, AIIL −78.4, ALLCARGO −62.0, ANANDRATHI −49.6, IRB −45.9. Zero false positives at 30%.

## 3. Shortlist filters now fail closed

**`excel_generator.py`** — `if pd.notna(x) and x < threshold` let `NaN` pass. A stock with no RS data cleared the "must be outperforming" test.

Now fails closed, with one deliberate exception. Two cases are handled differently:

- **Universe-wide RS outage** (index fetch *and* cache both failed): the filter can't be applied at all, so it's bypassed and the existing red banner — `⚠ RS vs NIFTY UNAVAILABLE THIS RUN — ranked on Accum Score only` — makes the degradation impossible to miss. Better than handing you an empty sheet.
- **One stock missing RS** (e.g. under 52 rows of history): excluded. It hasn't demonstrated leadership, so it doesn't belong on a Weinstein shortlist.

**Verified**

```
index available:    32 candidates, RS populated 32/32
index missing:      red banner fires, ranked on Accum only (was: 43 silent passes claiming "RS≥0%")
stock with 40 rows: correctly excluded
```

## 6. NEW — entry and exit levels

**`calculations.py: calculate_base_levels()`**, config block `base_levels`. Five new columns on both the Shortlist and the Report:

| Column | Meaning |
|---|---|
| `Pivot` | resistance line of the base — the price Weinstein buys *through* |
| `→Pivot %` | negative = not yet triggered; positive = how far past the buy point |
| `Stop` | `max(base low, 30WMA)` less a 2% buffer |
| `→Stop %` | how much room to the stop, as % of price |
| `Base Wks` | weeks price stayed inside the base |

**Two design decisions worth knowing:**

*The pivot skips the last 4 weeks.* Without that, a stock that just broke out redefines its own pivot to the breakout high and `→Pivot %` collapses to ~0% for everything that has already moved. Skipping keeps the pivot anchored to pre-breakout resistance, which is what tells you whether you're early or chasing.

*The stop is `max(base low, 30WMA)`.* Early in a move the base low is higher and binds; as the stock advances the 30WMA rises above it and takes over. That reproduces Weinstein's "trail the stop under the 30WMA" automatically. If the WMA sits above price (a Stage 2 pullback) it would imply a stop above the entry, so it falls back to a fixed 10% below price.

**Colour coding:** `→Pivot %` green in the −2% to +5% entry window, amber beyond +15% (chasing). `→Stop %` pink beyond 15% (poor risk regardless of how good the signal looks). `Why` gained `AtPivot`, `Ext__%` and `Risk__%` tags.

**Verified across 146 tickers**

```
invariant stop < close: 0 violations
→Stop %:  p25 6.6%   median 10.0%   p75 13.0%
Base Wks: median 14   max 36
no identifiable base: reported blank rather than guessed
```

Sample output:

```

MARICO         +0.6%    6.9%  Acc6; Dlv60%; AtPivot
INDUSINDBK     -0.1%    9.7%  Acc5; RS12%; Tight; AtPivot
LLOYDSME       +3.2%   11.2%  Acc6; AtPivot
```

MARICO and INDUSINDBK are sitting on their pivots with 7–10% risk. DIVISLAB looks strong on every other metric but is 22% extended with a 20% stop — the columns now say that out loud. BORORENEW has no clean base, so it's blank rather than fabricated.

**Practical effect:** on the 150-ticker test run, 14 names passed the shortlist and **5 were in the actionable −2% to +5% entry window.** That's the number that matters — it turns a shortlist into a short list.

## 7. Two blockers found during pre-flight for `--mode initial`

### 7a. The merge would have doubled every overlapping trading day

Every date in the existing pickles carries the wall-clock time of the original
run — `2025-11-07T21:19:19.687191`. The fixed fetcher writes
`2025-11-07T00:00:00`. `merge_new_data` de-duplicates on exact `date` equality,
so the two would not have matched and **both rows would have been kept**:

```
legacy cache:   192 rows @ 21:19:19
incoming fetch: 490 rows @ midnight
overlap:        192 trading days
DUPLICATE dates before fix: 192      after fix: 0
```

192 doubled days would have halved the real span of every rolling window — the
36-day volume MA over 18 actual days, the 252-day 52-week high over 126, weekly
WMA bars counted twice.

`merge_new_data` now normalises **both** sides before de-duplicating, so the
merge is correct regardless of which vintage of cache file is on disk, and
`save_ticker_data` then rewrites the file normalised. `get_latest_date` also
normalises, so the incremental window no longer inherits a time-of-day.

### 7b. The bhav-copy LRU was one slot too small — 22× the downloads

A 730-day window is **501 trading dates**; the LRU held **500**. The run scans
that same date list once per ticker batch in the same order, and a sequential
scan of N+1 items through an N-slot LRU evicts each entry just before it is
next needed — a 100% miss rate.

```
capacity 500:  22 batches x 501 dates = 11,022 bhav copies (~15 GB, many hours)
capacity 700:                             501 bhav copies (~0.7 GB)
```

Raised to 700. Peak memory for the cache is ~90 MB, so there's no real cost.

## Open by design

- **Corporate actions are excluded, not adjusted.** A stock that split 18 months ago stays unshortlistable even though its recent history is clean. Back-adjusting prices would fix the signals *and* return those names.
- **`base_depth_pct` clusters near its 25% cap** by construction — the walk-back stops when it breaches the band, so depth mostly reports "hit the limit". `Base Wks` is the discriminating field. Tighten `base_max_depth_pct` to 15% if you want stricter bases.
- **`rs_ratio` is a 52-day ROC spread**, not Mansfield RS, and it's absolute rather than a cross-sectional percentile.
- **Scores are equal-weighted votes, and there's still no backtest.** Nothing in the repo tests whether `accum_score` or the pivot signal predicts forward returns. Until that exists, treat the ranking as a well-constructed research queue rather than a validated edge.
